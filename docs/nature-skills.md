# Nature Skills：逐项使用说明

[返回首页](../README.md) · [其他技能完整目录](local-skills-catalog.md) · [科研工作流](research-workflows.md)

本页基于已安装版本 `c8599197` 的说明编写，列出 **22 个功能技能 + 1 个内部支持包**。下面的示例直接放入 Codex 聊天框；示例中的文件名、方向和输出目录需要换成自己的材料。提交后，AI 读取对应技能并按实际工具条件执行。示例没有被批量运行，不代表相应外部服务已经配置。

## 一、检索、下载与引用

### 1. nature-academic-search：跨来源文献检索

**用途：** 按主题搜索文献，构建检索式，核对引用，以及转换、管理 BibTeX/RIS/NBIB 等参考文献文件。也有独立他引审计等专门流程。

**准备与输出：** 提供研究主题、关键词、年份、文献类型和筛选规则；得到带来源的候选清单、筛选理由和按需求导出的引用文件。已有完整记录的格式转换可以离线处理。

```text
请使用 $nature-academic-search，检索 2024—2026 年关于大模型安全评测的论文。
优先会议论文和可访问全文，先给我 10 篇，区分预印本与正式发表版本，
列出研究问题、评测设置、DOI/链接和筛选理由，并导出 BibTeX。
```

**依赖与边界：** 在线检索需要可用网络或相应检索工具；专用 MCP、PubMed 联系邮箱或出版商密钥按来源按需配置，不是全部必需。查到标题不等于读过全文；只读摘要时应明确标注。

### 2. nature-downloader：获取授权范围内的全文

**用途：** 根据 DOI、标题或链接获取论文正文及可选 Supporting Information（SI，补充材料），选择开放获取、出版商 API 或用户已有机构访问途径。

**准备与输出：** 给出明确论文列表、保存目录、是否要 SI、是否只接受 PDF。输出实际下载文件及来源/失败状态。默认流程要求先明确 SI 选择；在指令中写“只要正文，不要 SI”即可说明。

```text
请使用 $nature-downloader，下载下面 3 个 DOI 的正文 PDF 到我指定的 papers 文件夹。
只要正文，不需要 SI；优先合法开放版本。无法获得真正 PDF 的条目请报告失败原因。
DOI 列表：……
```

**依赖与边界：** 技能声明需要 Node.js 22+ 与 Python 3；机构访问等浏览器路线还需要用户已登录的 Chrome 会话及相应控制能力。出版商 API 是按需选项，密钥不等于每篇文章都有全文权限。不能把登录网页或 CAJ 改扩展名冒充 PDF；不会因为安装技能而自动开通知网权限。

### 3. nature-citation：为论断寻找 Nature/CNS 范围的支撑文献

**用途：** 根据论文段落中的具体论断，查找 Nature 系列或 CNS（Cell、Nature、Science）及指定子刊范围内的支持来源，建立“论断—证据”映射并导出参考文献。

**准备与输出：** 提供段落、期刊范围和日期限制；输出支持关系、支持强度、未获支持的主张与引用文件。

```text
请使用 $nature-citation，为以下段落补充引用，范围为 Nature 系列，年份不限。
逐句判断找到的论文是否真正支持该论断；没有直接证据的句子请标记，
不要只因标题相关就当作支持，最后导出 RIS。段落：……
```

**依赖与边界：** 需要在线查证。计算机方向如果关注 ACL、ICLR、NeurIPS、CCS、NDSS 等会议，通常先用 `nature-academic-search`，避免被 Nature/CNS 范围限制。

### 4. nature-ref-verifier：核查参考文献

**用途：** 检查 DOI 是否指向正确文献，逐字段核对标题、作者及顺序、年份、卷期和页码，定位拼接、错引和版本差异。

**准备与输出：** 输入参考文献列表、`.bib` 文件或单条记录；输出有来源的差异清单、修正建议和无法确定的字段。

```text
请使用 $nature-ref-verifier，核查 references.bib 中的全部条目。
先验证 DOI 与标题是否对应，再检查作者顺序和出版信息。
输出 Markdown 表格：原字段、核验字段、来源、问题、建议。先不要改 Zotero 数据。
```

**依赖与边界：** 依赖可访问的 Crossref、出版商等来源；单个来源查不到不能直接判为伪造。同步改 Zotero 还需要对应连接与写入授权；单纯核查不要求配置 Zotero。

### 5. nature-literature-pipeline：连续文献发现与归档

**用途：** 将多来源检索、粗筛、细读、评分、摘要交付和去重归档连成流程，适合持续关注一个研究方向。

**准备与输出：** 提供关键词、时间范围、候选数量、保留数量、评分标准和归档目录；得到分级文献清单、阅读笔记及来源层级标记。

```text
请使用 $nature-literature-pipeline，先做一次手动文献筛选。
方向：大模型安全评测；检索 30 篇候选，筛出最相关的 5 篇。
标注每篇是读到全文、摘要还是元数据，按 DOI/arXiv ID 去重，
保存到我指定的 literature 文件夹。本次不设置定时任务，不发送外部消息。
```

**依赖与边界：** 单次本地输出不需要飞书或 Telegram。定时执行、通知和归档平台需要另行配置；技能不会因为安装完成就每天运行，也不能假定其 Hermes cron 示例可原样用于 Codex。

## 二、阅读、翻译与研究理解

### 6. nature-paper-xray：讲透一篇论文

**用途：** 重建论文问题、方法动机、关键设计和证据边界，并用具体数字讲清重要公式。适合“看过摘要，但不明白为什么这样设计”。

**准备与输出：** 最好提供正文、附录及补充材料；输出中文 Markdown 长篇讲解，区分原文陈述、阅读推断和原文未报告的信息。

```text
请使用 $nature-paper-xray，讲透我上传的论文。
按研究问题、核心假设、方法流程、关键公式算例、实验对照、证据边界讲解。
我没有机器学习实验基础；每个关键公式都给出能算到结果的微型例子。
不要把作者未报告的设置当成默认事实。
```

**依赖与边界：** 以可读论文为基础，扫描版可能需要 OCR。它侧重理解，不默认做文献检索、全文翻译或给出录用评价。

### 7. nature-paper-card：结构化精读卡

**用途：** 将一篇论文整理成方便积累和比较的研究卡，重点记录方法、实验如何支撑主张、局限和后续研究想法。

**准备与输出：** 提供论文或已有 `nature-reader` 材料；得到结构化 Paper Card，并保留可验证的位置锚点。

```text
请使用 $nature-paper-card，把这篇论文整理成中文精读卡。
重点列出每项贡献对应的实验、基线是否公平、缺失的消融、复现所需材料，
以及 3 个仍需验证的问题。所有重要判断附页码或章节位置。
```

**依赖与边界：** PDF/源映射输入使用随包的准备脚本，相关 PDF 解析依赖需可用。只有摘要时应交付明确受限的卡片，不能补写未读的实验；与 `paper-xray` 相比更强调固定结构与长期积累。

### 8. nature-reader：中英对照阅读材料

**用途：** 生成能追溯原文的中英对照阅读材料，保持正文、图表、公式与来源的对应，也可以只回答指定段落的问题。

**准备与输出：** 输入 PDF、网页、DOI/arXiv 信息或粘贴文本；完整阅读任务通常产生 `paper.md`、来源映射和术语记录，具体以任务范围为准。

```text
请使用 $nature-reader，只处理这篇论文的第 2 节。
生成中英对照 Markdown，保留公式、图表引用和原文定位，
将同一术语的译法统一；不扩展成全文阅读器。
```

**依赖与边界：** PDF 提取、扫描识别或在线获取按输入类型需要工具。优先选择它来做可检索、可引用的文本对照；不要将它等同于逐页保留原版式的中文 PDF。

### 9. nature-paper-trans：图片型中文 PDF

**用途：** 把英文 PDF 的指定页或全文逐页翻译成简体中文页面，尽量保留原来的分栏、图表、公式和版面关系，最终合成图片型 PDF。

**准备与输出：** 给出英文 PDF、明确的 PDF 实际页序、术语要求。最终交付中文 PDF；通常保留各源页尺寸。图片型 PDF 不等于可编辑或可搜索文本的 PDF。

```text
请使用 $nature-paper-trans，翻译这个英文 PDF 的实际第 1—2 页。
保留源页面尺寸，不改为 A4；术语 model inversion 译为“模型反演”。
先只做这两页，交付中文 PDF，并说明检查中发现的问题。
```

**依赖与边界：** 此安装版本明确使用**内置 image_gen 生图工具**，并需要 Python 3.9+、PyMuPDF 和 Pillow。它不是现有 Zotero PDF2zh/DeepSeek 翻译接口。每页每轮只有一次生图机会，无自动重试；公式、数字和译文需对照原文。先试少量页面更便于判断是否符合阅读需求。

### 10. nature-social-science：研究选题与论证自检

**用途：** 面向社会科学及相邻领域，将宽泛兴趣转成可讨论的研究问题，检查文献版图、证据路线、可行性和结论边界。

**准备与输出：** 给出兴趣、已有文献、数据条件、时间与训练背景；得到分阶段研究状态、候选问题和待验证事项，而非保证新颖的“标准题目”。

```text
请使用 $nature-social-science，帮我把“学生如何使用生成式 AI”收敛成研究问题。
我有访谈条件，但还没有数据。先梳理现象、已有解释与可能的证据路线，
不要因为“研究少”就认定存在有价值的研究空白。
```

**依赖与边界：** 文献查证阶段需要检索；材料内推敲不必先配置 API。计算机算法论文可以借鉴问题澄清方法，但它的主要适用范围仍是社科及相邻领域。

## 三、实验记录、统计与绘图

### 11. nature-experiment-log：实验记录整理

**用途：** 将本地日志、图片、文字和可处理的语音材料整理成有元数据的 Markdown 实验记录，保存原始材料关联和异常信息。

**准备与输出：** 提供真实日期、实验目的、配置、日志、结果和输出目录；得到带 YAML frontmatter 的实验日志及原始材料索引。

```text
请使用 $nature-experiment-log，将本次实验的配置 JSON、控制台日志和结果表
整理成 Markdown 日志，保存到我指定的 experiments 文件夹。
分别记录计划样本数、成功请求数、基础设施失败数、模型版本和随机种子，
缺失字段写“未记录”，保留原始文件链接。
```

**依赖与边界：** 核心本地流程不要求飞书或 Obsidian；语音需有可用转录能力。它整理事实，不应将 API 失败写成模型拒答或将未运行实验写成完成。

### 12. nature-statistics：统计报告与设计审查

**用途：** 检查独立实验单位、样本数、重复、误差条、置信区间、检验、多重比较和正文/图注是否一致。

**准备与输出：** 提供设计、结果、统计方法段和图注；得到问题清单、缺失事实与可直接替换的表述。提供数据并明确要求时才计算新分析。

```text
请使用 $nature-statistics，审查这张实验结果表和统计说明。
检查 API 请求失败应如何进入分母、单个随机种子能否支持稳定性结论、
误差条与置信区间是否有依据。先审查，不进行新计算，不替我补造数值。
```

**依赖与边界：** 文字审查不必先安装统计软件；实际计算需数据和相应 Python/R 环境。它主要解决统计报告是否可信、清楚，不能脱离实验设计随便指定一个检验。

### 13. nature-figure：论文图与可编辑示意图

**用途：** 使用 Python 或 R 绘制数据图、多面板图，检查图注和导出质量；另有手工可编辑 SVG 示意图与明确请求的 AI 图形摘要路线。

**准备与输出：** 数据图需要真实 CSV/Excel、字段解释、单位、分组和误差定义；输出绘图代码、图件及检查结果，格式按任务指定。

```text
请使用 $nature-figure，使用 Python，根据 results.csv 绘制分组柱状图。
横轴为模型，纵轴为有效响应中的成功率；同时显示每组有效样本数。
若数据不足以计算置信区间，请指出，不自行编造误差条。
输出 SVG、PDF 和可复用绘图脚本。
```

**依赖与边界：** 数据图选择 Python 的 matplotlib/seaborn 或 R 的对应工具链；首次未选后端时该技能会询问。仅审图不必先选后端。SVG 示意图、AI 生图与数据绘图是不同路线，DeepSeek 文本 API 不能自动替代图像生成服务。

## 四、汇报、幻灯片与材料转换

### 14. nature-paper2ppt：论文转组会汇报

**用途：** 根据论文或阅读笔记制作中文学术 PPTX，包括叙事、原文图表、来源和演讲备注；也可修改现有汇报。

**准备与输出：** 论文、时长、听众、需要讲清的问题及模板；要求制作文件时应交付真实 `.pptx`，而非只有大纲。

```text
请使用 $nature-paper2ppt，把这篇算法论文做成 12 分钟中文组会汇报。
听众是刚入学的计算机研究生。按问题、方法、一个具体算例、实验和局限组织，
注明原文图表出处，加入讲者备注，输出 PPTX 并检查渲染效果。
```

**依赖与边界：** 需要可用 PPTX 生成与渲染工具链，随包有质量审查脚本。不能仅因源论文结果看起来完整就编造演讲中的新实验。

### 15. nature-image2ppt：截图重建可编辑 PPT

**用途：** 将已有幻灯片截图、扫描页或仅含图片的 PPTX 重建为对象级可编辑的 PowerPoint；重点是复原结构，不是替论文重新构思报告。

**准备与输出：** 清晰截图/扫描 PDF/PPTX、目标范围和可编辑要求；输出 PPTX 与质量检查结果，说明仍以位图保留的复杂区域。

```text
请使用 $nature-image2ppt，将这 3 张幻灯片截图还原为可编辑 PPTX。
文字、方框、直线和常规箭头尽量使用原生对象；
复杂图片可以保留位图，但明确标注。逐页对照截图检查后交付。
```

**依赖与边界：** 涉及页面分配、构建、渲染和 QA 工具；公式还需相应渲染能力。安装了说明文件不保证工具链已满足。它与 `paper2ppt` 的区别是“重建现有页面”与“根据论文制作新的报告”。

## 五、写作、开题与投稿

### 16. nature-writing：根据证据起草论文

**用途：** 起草或重构科学论文的论证和章节，以及首次投稿相关材料。适合需要组织研究故事、串联证据的写作。

**准备与输出：** 研究问题、方法、真实结果、相关文献、目标读者和章节范围；得到草稿、证据映射及待补信息。

```text
请使用 $nature-writing，根据我提供的方法说明和实验表起草中文 Methods。
保留模型、数据、预算、失败处理和评测口径，不添加未完成的实验。
缺少复现参数时单独列为“作者需补充”，不自行填写。
```

**依赖与边界：** 普通文本起草不必先配置专用 API；查证、LaTeX 编译、文档导出另需对应工具。目标为其他期刊/会议时明确其要求，不机械套用 Nature 格式。

### 17. nature-polishing：修改已有文字

**用途：** 润色、学术翻译、精简已有段落，保持事实、术语和证据强度；也支持按需求处理稿件 LaTeX 排版问题。

**准备与输出：** 原文、目标语言、字数/风格和不可改术语；得到修订文本及必要的修改解释。

```text
请使用 $nature-polishing，润色下面的英文实验分析，缩短约 20%。
不要把 suggests 改成 proves；保留所有数值、引用和限定条件。
给出修改版，并用中文说明影响科学含义的修改。原文：……
```

**依赖与边界：** 纯语言修改只需原文；编译时才需要相应工具。需要从头起草或重构核心论证时应使用 `nature-writing`。

### 18. researchwrite：开题报告与研究计划

**名称提醒：** 安装文件夹叫 `nature-proposal-writer`，但 `SKILL.md` 中的实际技能名是 **`researchwrite`**。调用时优先写 `$researchwrite`。

**用途、材料与输出：** 根据文献基础、研究问题、已有证据和资源约束，起草、修改或审查开题报告、研究计划、项目申请书，标出可行性、里程碑和待确认内容。

```text
请使用 $researchwrite，根据这份文献清单和已有实验记录建立开题报告大纲。
先区分已验证事实、研究假设与计划工作；围绕研究问题、证据路线、
可行性、风险和 6 个月里程碑展开。当前只生成大纲，不写成已取得的成果。
```

**依赖与边界：** 文献验证、DOCX 导出等按实际任务需要工具；不保证新颖性、资助或通过开题。其高级审查模式涉及独立评估，不应将同一上下文中的多段文字称为独立审查。

### 19. nature-data：数据与代码可用性

**用途：** 起草、审查 Data Availability 和 Code Availability 声明，整理数据集获取方式、存储仓库、标识符和 FAIR 元数据。

**准备与输出：** 提供实际数据与代码列表、仓库链接、访问限制和许可；输出声明草稿、数据到位置的对应关系与缺失字段。

```text
请使用 $nature-data，根据以下真实仓库和数据清单起草中英文可用性声明。
区分公开数据、受限制数据和第三方数据；缺少 DOI 的地方保留待填项，
不要编造上传状态、许可证或访问条件。材料：……
```

**依赖与边界：** 起草不等于已经上传数据、创建 DOI 或开放代码；不会处理一般的数据清洗。真实上传、发布和访问控制是另外的操作。

### 20. nature-reviewer：模拟审稿

**用途：** 从审稿角度检查稿件的贡献、证据和技术有效性，给出有位置依据的主要与次要问题。

**准备与输出：** 完整稿件/明确片段、研究材料和目标期刊标准。默认结构为 3 份相互隔离的模拟报告及事后综合；用户可以指定更小范围。

```text
请使用 $nature-reviewer，只审查我这篇稿件的实验设计。
本次只需要一份报告，列出有原文位置的主要问题、次要问题及修正建议。
不要评价未提供的补充材料，也不要预测真实期刊的录用结果。
```

**依赖与边界：** 完整多报告模式需要真正隔离的上下文/调用能力，不能把同一上下文的角色扮演称为独立盲审；没有该能力应明确限制。它不是期刊正式审稿或录用保证。

### 21. nature-response：回复审稿意见

**用途：** 逐条拆解审稿意见，组织修改行动、回复信、返修 cover letter 及稿件修改记录。

**准备与输出：** 审稿意见、现稿、真实已完成修改和证据；得到逐点回复、行动对应表及按需求形成的返修材料。

```text
请使用 $nature-response，根据审稿意见和实际修改记录起草英文逐点回复。
每条列出意见、回应、修改位置和证据。尚未完成的实验保留待办，
不要写“已完成”；不同意的意见给出专业且有依据的解释。材料：……
```

**依赖与边界：** 只写回复需要文本材料；制作 LaTeX/标记稿返修包还需编译与一致性检查。改动正文后，应重新核对回复中的引文、页码和行号。

### 22. nature-paper-to-patent：技术交底与专利草稿

**用途：** 将论文或发明材料转为有证据来源的中文技术交底书、权利要求与说明书草稿，检查特征是否有原文依据。

**准备与输出：** 真实技术方案、论文/代码/实验材料、已有披露和权属相关事实。按模式输出技术交底 Markdown/DOCX 或专利草稿材料及待确认问题。

```text
请使用 $nature-paper-to-patent，根据我的技术说明和实验材料整理技术交底书草稿。
逐项标记哪些技术特征有材料支撑，哪些仍需我确认；
先输出中文 Markdown，不推断发明人、权属、法律充分性或可授权结论。
```

**依赖与边界：** PDF 解析、DOCX 生成、现有技术检索按所选路线需要相应依赖；安装包内有不同路线的 requirements。材料整理和草拟不能替代正式权属、公开时间及专利性判断。

## 六、共享支持包

### nature-shared：其他技能调用的公共资料

**用途：** 保存共同术语、论文类型划分、文本一致性要求和特定期刊格式参考，供写作、阅读、汇报等技能按需读取。

**使用方法：** 不单独调用，也不把它算作第 23 个用户工作流。保留与其他 `nature-*` 目录的相对结构即可；不要只复制每个技能的 `SKILL.md` 后删除它。

## 容易选错的组合

| 容易混淆 | 怎么选 |
| --- | --- |
| paper-xray / paper-card | 前者讲透推理和公式；后者生成结构化长期阅读卡 |
| reader / paper-trans | 前者中英对照文本与来源定位；后者通过生图生成图片型中文 PDF |
| academic-search / citation / ref-verifier | 前者广泛找文献；中者在限定期刊范围找论断支撑；后者核查已有引用 |
| writing / polishing / researchwrite | 论文起草与重构 / 已有文字修改 / 开题和研究计划 |
| reviewer / response | 提出模拟审稿问题 / 作者回复真实意见 |
| paper2ppt / image2ppt | 根据论文新做报告 / 根据截图重建已有页面 |
| data / statistics / figure | 数据代码共享声明 / 统计报告与设计审查 / 绘图与图件检查 |

## 配置与检查

1. 先试一个小任务，例如解释一个公式、检查一段文字、生成一页示例，不默认处理全文或调用整套外部服务。
2. 让 AI 明确本次读取了哪个技能、已有工具是否满足该流程；工具缺失应报告，不能声称已执行。
3. 网络检索、下载、生图、第三方 API、消息推送与自动化的依赖不同；有 DeepSeek 文本 API 不代表具备所有能力。
4. 最终检查论文来源定位、公式、数值、引用、文件是否能打开，以及结果是否在指定目录。未验证项保留为未验证。
