# 科研复现：按阶段组合技能

[返回首页](../README.md) · [Nature 技能详解](nature-skills.md) · [其他技能目录](local-skills-catalog.md)

下面是一条从零基础开始的使用路线。Skill 帮助组织工作与核对证据，实验设计、模型选择和结果解释仍需要理解。每一步都可以单独完成，无须一次调用整套技能。

## 1. 先读懂论文，再判断复现范围

```text
请使用 $nature-paper-xray，阅读我提供的论文和附录。
我想学习复现，先解释研究问题、输入输出、方法各模块和实验设置。
区分论文明确报告的信息、你的阅读推断和缺失信息。
本次不下载代码、不运行实验，输出中文 Markdown。
```

检查：是否能说出方法要解决什么问题；基线是什么；改进依赖哪些条件；模型、数据、预算和评测器是否明确。随后可以用 `nature-paper-card` 保存固定结构的笔记，不必重复做全文翻译。

## 2. 认识 GitHub 仓库

```text
请使用 ecc:codebase-onboarding，读取这个本地仓库。
按新手能理解的方式解释 README、requirements、配置示例、数据目录、
src、models、prompts、主程序入口和结果目录的作用。
列出运行链路和待确认依赖；先不要安装软件或调用 API。
```

准备：论文对应版本的仓库、README、依赖文件和配置示例。检查：解释器是否属于本项目环境，示例配置是否只是模板，数据是否完整，外部模型服务是否真的可用。不要把示例中的模型名称当作已开通的服务。

## 3. 先跑最小验证，再扩展实验

```text
请根据项目 README，为我写一份最小验证的教学步骤。
逐条说明操作位置、命令含义、预期输出和失败时检查什么。
先用无害样例验证数据加载、模型请求、评测解析和结果保存。
不要替我执行；需要付费 API 的步骤标出预计请求数量。
```

这里未强制指定一个 Skill：普通的教学说明也能完成。若已有明确报错，再调用 `superpowers-systematic-debugging`，并附完整错误、配置中不含密钥的部分、最近修改和复现方式。

```text
请使用 $superpowers-systematic-debugging，分析下面的报错。
先区分网络/授权失败、程序异常和模型正常拒答，基于日志提出可验证假设。
每次只建议一个最小检查，说明预期结果如何支持或排除假设。
```

## 4. 记录每轮实验，而不是只保留最终百分比

```text
请使用 $nature-experiment-log，整理这一轮的配置、日志和结果 JSON。
记录数据版本、模型标识、API 地域、实验预算、随机种子、起止时间、
总样本数、有效完成数、基础设施失败数、成功数与输出文件。
将真实观察和我的推测分开，输出到我指定的 Markdown 目录。
```

检查：每个计数能否追溯原始记录；重试是否进入请求预算；未完成的样本是否被错误记作失败；每条结果是否保留对应配置。不要将 API 认证失败解释为模型安全能力强。

## 5. 先明确统计口径，再绘图

```text
请使用 $nature-statistics，审查这份实验设计和结果汇总。
分别列出全部计划样本、有效完成样本和基础设施失败样本。
检查成功率分母是否明确，以及不同模型之间的预算和数据是否可比较。
若只有一个随机种子，不要生成跨种子标准差或据此声称结果稳定。
```

成功率的分母随研究方案而定，不能看到 API 失败就自动删掉所有失败记录后宣布得到新的正式 ASR。可以同时报告计划样本覆盖、有效响应中的条件成功率与基础设施失败，并解释实验协议及偏差；它们回答不同问题。

```text
请使用 $nature-figure，使用 Python 绘制已核对的数据。
展示有效完成率、基础设施失败占比和协议规定的成功率，明确各自分母。
保留缺失标记，不把无效对照组画成 0% 成功率。输出 SVG、PDF 和脚本。
```

## 6. 汇报与写作

```text
请使用 $nature-paper2ppt，根据论文、复现日志和核对过的结果表制作中文组会 PPTX。
明确分开作者原实验、我的替代模型设置、已完成结果和待验证问题。
请用一页说明哪些差异影响与原论文结果的可比性，并加入讲者备注。
```

写论文方法与结果时使用 `nature-writing`；只改现有文字使用 `nature-polishing`；整理开题方案使用 `researchwrite`。给 AI 的材料应包括实际完成情况，不能让语言润色把计划改成成果。

## 7. 常见问题

### 安装后为什么仍然提示缺少工具？

安装的是说明、模板和脚本，不包含所有 Python/R 包、MCP 服务器、CLI、浏览器连接、授权账号或模型额度。让 AI 指出当前任务具体缺什么，再按需处理。不要在聊天中粘贴密钥；可在本地配置或授权界面填写。

### 我有 DeepSeek API，所有 Skill 都能用吗？

不能由此推断。许多文字处理任务使用当前助手即可；在线数据库、浏览器操作、文档渲染和生图各有工具要求。尤其当前版本 `nature-paper-trans` 使用内置生图，而不是 DeepSeek 文本翻译。

### 为什么文件夹名称与调用名称不一样？

以 `SKILL.md` 的名称和当前宿主选择器为准。例如 `nature-proposal-writer` 调用 `researchwrite`；插件技能可能带 `ecc:`、`google-drive:` 等前缀。完整目录已给出当前调用入口。

### `$技能名` 没反应怎么办？

先在聊天框用自然语言写“请使用某某技能”；确认新会话的可用目录中有它。目录里没有时，检查安装位置、宿主是否支持该路径或插件是否启用。磁盘缓存不等于启用；不要直接修改插件缓存来强行加载。

### 同一种任务有好几个技能怎么办？

优先选择目标最明确的一个。例如论文汇报选 `nature-paper2ppt`，普通演示文稿选 `presentations:Presentations`；本地表格选 `spreadsheets:Spreadsheets`，已连接的在线表格选 `google-drive:google-sheets`；PDF 文本阅读与页面视觉检查也可以分别选对应能力。不要默认把所有同类流程串联执行。

### 能在 PyCharm 中使用吗？

Skill 首先属于读取它的 AI 宿主。把文件放到 Codex 全局目录，不会自动安装到 PyCharm。可以让 Codex 按技能整理步骤、代码和运行配置，然后在 PyCharm 中运行项目；若通过 IDE 中的 AI 插件调用，还需确认该插件自己的技能支持和加载规则。

### 自动文献推送会在关机后继续运行吗？

要看调度器运行在哪里。纯本地任务通常需要电脑和应用处于可执行状态；技能自身的描述不会创建常驻云服务。本次只建立手册，没有设置文献推送或定时任务。

## 交付结果的最小核对

| 输出 | 应检查什么 |
| --- | --- |
| 检索清单 | 来源能打开；预印本与正式版区分；全文/摘要/元数据层级明确 |
| 精读材料 | 重要判断能定位原文；公式和数值不靠猜测 |
| 实验记录 | 配置与结果对应；失败类型可追溯；没有密钥 |
| 图表 | 分母、单位、样本数、误差定义明确；缺失值未冒充零值 |
| PPT/Word/PDF | 实际生成文件可打开；必要时已渲染并检查；不能只有生成脚本 |
| 写作与回复 | 未做的实验没有写成已完成；引文与真实来源对应 |

本页示例用于研究工作组织和教学，不复述具体有害目标或攻击提示词。
